# UIテスト環境

## 最短の確認方法

プロジェクト直下の `open-ui-preview.cmd` をダブルクリックする。

ローカルファイルだけで動作し、サーバーや依存パッケージの導入は不要。本番の `popup/popup.html`、`popup/popup.css`、`popup/popup.js` を直接読み込む。

確認できる項目:

- Chromeカラー: Rose / Blue / Green / Violet / Neutral / Custom
- Customの基準色1色から生成されるライト／ダーク配色
- Customカード内の色ピッカーとカラーコード直接入力
- ライト / ダーク
- 整理成功 / エラー
- 影あり / なし
- 処理中、完了、エラー、キャンセル、ポップアップを閉じる動作
- 確認後にタブや分類設定が変わった場合、ダイアログを閉じず最新件数へ差し替える再確認
- 短いテスト期限を使ったUndo・分類修正・設定画面ヒントの自動失効
- Service Worker起動直後を模した遅い状態読込みと、処理中から完了への自動更新
- キーボードフォーカス
- `設定 ↗` から別タブで開く分類設定
- 最優先ドメインの追加・削除、入力検証、重複防止
- 分類グループ単位の使用停止、停止中表示、保存、再有効化
- Chromeタブグループ色の変更、保存、変更の取り消し
- 設定画面の初期表示が分類グループであること
- UIテーマの即時プレビュー、保存、変更の取り消し
- 未分類タブをOthersへまとめる設定（既定オフ）、保存、変更の取り消し
- 未登録サイトの自動分類をオンにした直後の権限状態、保存、オフ保存時の権限解除
- 設定画面を2タブで開いたときの外部更新の自動反映、領域別の統合、同一領域の競合停止

`Undo期限` を `2秒` にすると、ポップアップの完了画面と、そこから開いた設定画面の期限切れ表示を短時間で確認できる。本番の保存値や30分の既定動作には影響しない。

`起動状態` を `処理中` にすると、遅い状態応答を一つずつ読みながら、処理中表示から完了画面へ自動で移る。Service Worker起動直後や中断復旧時の表示確認に使う。

設定画面の一時的な読込み失敗は、`options/options.html?preview=1&loadFailure=refresh#organizer` を開いて `更新` を押すと再現できる。一覧と選択を残したまま操作だけを止め、自動再確認後に復帰することを確認する。

## Chrome拡張としての実機テスト

1. Chromeで `chrome://extensions/` を開く
2. デベロッパーモードを有効にする
3. 「パッケージ化されていない拡張機能を読み込む」を押す
4. このプロジェクトのルートフォルダーを選択する
5. ツールバーの拡張機能アイコンを押す

ファイルを変更した後は、`chrome://extensions/` にある拡張機能カードの再読み込みボタンを押す。

## 境界

UI Labはタブを実際には変更しない。設定画面で保存した内容もUI Lab専用のローカル領域へ保存され、本番設定には影響しない。タブ整理そのものを確認する場合だけ、上記のChrome実機テストを使う。

分類グループの既定値と設定の正規化規則は実拡張と共通である。UI Lab専用に短縮した分類ルールは使わない。
