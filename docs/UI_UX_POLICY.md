# UI / UX 方針

この文書は製品として守る方針を定義する。現在の実装状況は [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md) に分ける。

## 優先順位

1. UI と操作体験
2. 操作上の不都合の解消
3. 分類ロジックや付加機能

動作することだけを理由に画面へ機能を追加しない。ユーザーに判断を求めるのは、誤操作を防ぐために必要な最小限にする。

## ポップアップの操作フロー

拡張機能アイコンを押した直後に確認を表示する。安価に算出できる対象件数と予定グループ数だけを予告し、ページ本文を読む補助分類の結果は確認前の件数に含めない。

確認画面を表示した時点の未グループタブ、分類設定、補助分類に必要な権限を状態トークンへ含める。確定までに分類結果へ関わる状態が変わった場合は整理を開始せず、最新件数を表示してもう一度だけ確認を求める。確定直後に新しく開かれたタブは今回の対象へ追加せず、URL・分類結果に関わるタイトル・ピン留め・グループ状態が変わった確認済みタブもそのまま残す。状態取得に失敗した画面からは整理を開始せず、主ボタンを `再確認` とする。

- `整理`: 現在のウィンドウのタブを整理する
- `キャンセル`: 何も変更せずポップアップを閉じる
- `設定 ↗`: 分類設定を別画面で開く。既に設定タブがあれば再利用する

選択画面やダッシュボードは表示しない。選択肢が実際に二つ以上必要になるまでは、内部のアクション定義だけを拡張可能に保つ。初期フォーカスはキャンセルに置き、Enterだけで整理を開始しない。

完了後は分類グループと移動したタブを確認できる。誤分類は、そのタブの `修正` から移動先を1回選ぶと、タブ移動と完全一致ドメインの登録を同時に行う。

修正候補は一度に一つだけ開き、開いた直後は最初の候補へフォーカスを移す。矢印キー・Home・Endで候補を移動し、Escで元の `修正` へ戻れるようにする。移動先がない場合は `修正` を表示しない。

完了画面には結果の近くに `元に戻す` を置き、Ctrl+Z / ⌘Zでも同じ直前操作を取り消せるようにする。表示はOSの標準修飾キーへ追従する。Undoは30分間、同じブラウザーセッションとウィンドウに限定し、ポップアップを閉じても再表示できる。整理後にユーザーが閉じたタブや別のグループへ動かしたタブは上書きしない。

完了画面を開いたままUndoの30分が過ぎた場合は、期限切れ操作を押させない。ポップアップでは `元に戻す` と分類修正を静かに取り除いて期限終了を通知し、設定画面ではCtrl+Zのヒントを自動で消す。フォーカス中の操作が消える場合だけ、安全な `閉じる` へフォーカスを移す。

Undo要求には画面が表示している操作IDを含め、後から完了した別操作を古い画面から取り消さない。応答だけが失われた場合は同じ操作IDで安全に再送し、直前の成功結果を再表示する。整理・再構成・グループ編集の応答を確認できない場合は、再実行を促す前に実行中ロックと新しいUndo記録を読み直す。処理中なら進行表示を保ち、完了済みなら結果として表示する。

処理中の状態確認は一度に一要求だけ送る。遅い応答へ次の要求を重ねず、画面の再開始・終了後に届いた古い応答は描画しない。これにより完了画面、開いた修正メニュー、キーボードフォーカスを後着応答でリセットしない。

設定画面の状態更新が一時的に失敗しても、最後に確認できたグループ一覧・選択・Undo表示を空にしない。ただし古い確認内容から変更操作は開始させず、短い有限回の自動再確認中は操作を無効化する。再確認できなければ一覧を残したまま手動の `更新` を案内する。

一覧の選択やChrome側の状態更新で項目を再描画するときは、操作していた項目へフォーカスを戻す。その項目がなくなった場合は新しい選択項目、さらに存在しなければ一覧の先頭へ移し、ページ先頭へフォーカスを落とさない。

分類グループと現在のタブグループ一覧は、それぞれ一覧全体を一つのTab停留点として扱う。上下矢印で循環し、Home・Endで端へ移動する。フォーカス移動だけでは選択を変えず、EnterまたはSpaceでユーザーが確定したときに右ペインを切り替える。

## 分類設定

設定画面を開いたときは分類グループの編集を最初に表示する。外観は補助設定であり、その後ろに置く。

画面左上の現在名を押すと、`分類設定` と `タブグループ整理` を切り替えられる。現在の作業名を主表示、`Smart Tab Grouper` を小さな副表示とし、中央のタブバーは追加しない。切替矢印だけを灰色の面で囲わず、ホバー時も一つのコントロールとして扱う。分類設定の自動保存待ちは切替後も保持し、切替メニュー内に状態印を残す。

扱う項目は次に限定する。

- 分類グループを使用するかどうか。停止中も登録内容は保持する
- タイトルやキーワードより先に判定する最優先ドメイン
- Chromeのタブグループとして表示する色
- 未登録サイトをページ内容から補助分類するかどうか
- 未分類タブを一つの `Others` にまとめるかどうか
- 拡張機能UIのカラーテーマ

左側で分類グループを選び、右側で選択中のグループだけを編集する。分類グループ一覧だけを独立したスクロール領域とし、見出しと「整理の動作」「外観」は固定する。グループ種類数が増えても共通設定への導線を押し出さない。

停止中の分類は一覧で色印を中抜きにし、`停止中` と使用中件数を表示する。編集画面の先頭に一つだけ使用トグルを置く。オフにしてもドメイン・色・キーワードは削除せず、同じ場所から再有効化できるようにする。

同じ完全一致ドメインを複数グループへ登録することは禁止する。`mail.google.com` と `google.com` のような親子ドメインは併用でき、ホスト名に一致する登録のうち最も長く具体的なドメインを優先する。

更新時に旧設定の欠損フィールドを理由として分類を無効化しない。`enabled` を省略した旧ルールは有効として扱い、明示的に無効化されたルールだけを無効のまま引き継ぐ。UI Labも実拡張と同じ既定ルールと正規化規則を使い、プレビュー専用の分類結果を見せない。

変更は700msの短い待ち時間で自動保存し、連続する色入力などは一回の書き込みへまとめる。画面上部には保存ボタンを置かず、`保存待ち`／`保存中…`／`保存済み`／`保存できません` と `戻す` だけを表示する。`戻す` は保存待ちならその編集を破棄し、保存後なら現在の設定タブで直前に自動保存した一回分だけを復元して再保存する。保存失敗時は変更を画面に保持し、容量以外の一時失敗だけを有限回再試行する。自動保存待ちのまま設定タブを閉じる、再読み込みする、または別ページへ移動するときはブラウザー標準の離脱確認を使う。完了画面や別の設定タブから設定が更新された場合、編集中でなければ自動反映する。分類ルール・整理動作・外観の異なる領域であれば、外部更新を取り込みながら編集中の変更を残す。同じ領域が別々に変更された場合だけ自動保存を止めて `更新あり` と表示し、`最新を読込` の1操作で外部更新へ揃える。自動保存の開始時と書き込み直前にも保存基準を再検証し、古い画面から新しいドメイン登録や設定をサイレントに上書きしない。

分類設定はChrome同期領域の1項目上限を超えない世代付きチャンクへ分け、全チャンクの書き込み後に参照先を一度だけ切り替える。分類グループが変わっていない外観・動作設定の自動保存ではチャンクを書き直さず、Chrome同期領域の書き込み回数を抑える。保存途中で失敗した場合は新しい世代を破棄し、直前の設定を残す。同期容量を超えた場合も編集中の内容を画面に保持し、削減して再試行できる理由を表示する。

設定の外枠は内容によって拡大させず、必要な場合だけ左右のペイン内をスクロールする。未分類タブは既定で何も変更せず、ユーザーが明示的にオンにした場合だけ、グレーの単一 `Others` グループへまとめる。

狭いウィンドウで画面全体を横スクロールさせない。720px以下では一覧ペインと編集ペインを縦に積み、一覧内と編集内容はそれぞれ独立してスクロールできる状態を保つ。520px以下では見出しと保存状態／復元操作を二段にし、長い名称が復元操作を押し出さないようにする。

## 外観とアクセシビリティ

Rose / Blue / Green / Violet / Neutral の5テンプレートと Custom を提供する。Customでユーザーが選ぶのは基準色1色だけとし、背景、文字、ボタン、枠線、影、ライト／ダーク配色はセマンティックトークンから自動生成する。色ピッカーとカラーコード入力はCustomカード内へ収め、選択によってカードや外枠の寸法を変えない。選択中は即時プレビューし、有効な入力を短い待ち時間で自動保存する。

- OS / Chrome のライト・ダーク設定に追従する
- Windowsの高コントラスト表示に対応する
- 通常の文字は背景とのコントラスト比4.5:1以上をライト・ダーク双方で保証する
- 操作の理解に必要なUI部品と境界線は隣接色とのコントラスト比3:1以上を保証する
- キーボードフォーカスを明示する
- 不要なアニメーション、装飾、画面遷移を増やさない

Chrome内部テーマの基準色を取得する公開APIがない間は、ライト／ダーク追従と同じ色の役割・状態規則を優先する。画面キャプチャや過剰な権限でChromeの色を推測しない。

## 安全な整理

- 手動グループ、ピン留めタブ、Chrome内部ページを予期せず移動しない
- 整理開始前に実行中ロックと復元ジャーナルをセッション領域へ記録する
- 途中でService Workerが停止した場合は、期限切れの実行を次回起動時に安全に復元する
- Undoのスナップショットと進捗は `chrome.storage.session` に置き、Service Workerやポップアップの寿命に依存させない
- 拡張機能が所有するグループの照合情報は永続化し、Chrome再起動後は名前・色・所属ホストを再検証する
- 所有グループを一意に照合できない場合は同名グループを増やさず、その分類を変更しない
- 一部失敗を成功として扱わず、ロールバック結果と具体的な失敗状態を返す

## 本文による補助分類

本文判定は通常の分類を置き換えず、ドメインとタイトルで分類できなかったタブだけを補助する。

- 初期状態はオフ。オンにした時だけ、`scripting` と対象サイトへの任意アクセス権を説明して要求する
- トグルをオンにした直後にChromeの権限確認を表示し、許可されなければその場でオフへ戻す。保存時まで権限確認を遅らせない
- オフ設定から許可したサイトアクセスは自動保存が完了するまで一時権限として追跡する。完了前に設定タブを閉じる、再読み込みする、別ページへ移動する、またはブラウザーを再起動した場合は、ほかに保存待ちの設定タブがなく保存済み設定もオフであることを確認して権限を回収する
- Chrome側でアクセスが解除された場合はオン表示を残さず、設定画面と実行前の件数予告で利用できない理由を示す。オフを保存した時は任意アクセス権も解除する
- 未解決が最大30タブのときだけ実行し、31タブ以上では通常分類だけを使う
- 1回の全体予算は3秒、同時処理は最大3タブとする。予算を超えた候補は未分類のまま残す
- 最初にmeta descriptionと見出しだけを取得し、それで決まらない場合に限って本文の先頭から最大3,600文字までを取得する
- `input`、`textarea`、`contenteditable`、パスワード、フォーム値、iframe内、非表示要素は取得しない
- 抽出内容は外部へ送信せず、分類直後に破棄する
- Chrome内部ページ、拡張機能ページ、権限のないページ、破棄済みタブは読み取らず未分類のままにする
- 同じURL・タイトル・ルールの分類結果だけをブラウザーセッション中に30分キャッシュし、抽出内容は保存しない
- 1位がしきい値を超え、2位と十分な差がある場合だけ採用する。自信がなければ `Others` または未変更へ戻す

既定オンへの変更は、固定した評価セットで次を満たした後に判断する。

- 未登録かつ通常分類で未解決の実ページを最低1,000件用意し、カテゴリとサイト種別の偏りを記録する
- 2名が独立して正解ラベルと「分類不能」を付与し、不一致は3人目が裁定する
- ルール調整に使わない固定ホールドアウトで評価する
- 「採用した分類の適合率97%以上」「明確な誤分類1%未満」「カバレッジ70%以上」を同時に満たす
- 1・10・20・30タブでp50/p95、タイムアウト率、カバレッジを報告し、30タブのp95が3秒の全体予算内に収まる

単独の「正解率」だけは使わない。分類しなかったケースを除外して精度が高く見えることを防ぐため、適合率とカバレッジを必ず併記する。

## 設定ページからの整理

設定ページから整理を開始する場合も、ポップアップと同じ対象件数付きの確認を必須にする。分類設定の編集と実行を同じボタンにせず、自動保存が完了した設定だけを実行対象にする。

設定ページの確認中にタブや分類設定が変わった場合は、ダイアログを閉じずに最新件数へ差し替え、キャンセルへフォーカスを戻して再確認を求める。ダイアログ表示中に保留した一覧更新は、キャンセルまたは完了直後に反映し、背後の古い一覧を残さない。

安全な整理とUndoを共通処理として使い、次の順で追加する。

1. 現在のウィンドウを整理する確認付きアクション
2. 現在のタブグループ一覧と内容確認
3. 選択したグループを再構成する確認付きアクション
4. 名前・色・折りたたみ状態の編集
5. グループ順の変更
6. 結合・解除など復元が必要な操作

選択グループの再構成では、元グループに対応する分類が分かればその分類を残す。分からなければ最大の分類まとまりを残し、移動量を最小にする。判定不能タブと所有権が曖昧な移動先は元グループへ残し、元グループの名称・色・折りたたみ状態は変更しない。確認後にグループ状態が変わった場合は実行せず、再確認を求める。

既存グループの直接編集は、名前・Chrome標準の9色・折りたたみ状態だけを一つのモーダルで扱う。保存するまでは反映せず、編集中に外部変更があれば上書きしない。拡張機能所有グループの名前と色を変えた場合は所有権記録も追従させる。共有グループは共有先への影響が不明瞭なため、再構成と直接編集の対象外にする。

## 当面は追加しない

- 確認前の分類方法選択
- 常時表示の分析ダッシュボード
- 重複タブ削除など、整理と別目的の操作
- タブ内容の外部送信を前提にする分類

大規模な必須機能が判明した場合は、着手前に「必要になる条件」「UX上の理由」「想定する導線」をこの文書へ追記する。
